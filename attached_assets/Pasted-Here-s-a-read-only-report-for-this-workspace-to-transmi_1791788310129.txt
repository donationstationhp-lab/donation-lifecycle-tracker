## Authentication and staff access
The source code uses **Replit OIDC** (`https://replit.com/oidc`) with the authorization-code flow and PKCE. It creates a secure, HTTP-only session cookie with a seven-day lifetime.

Staff API access requires both a valid login and a server-side allowlist match by user ID or email. The code recognizes `STAFF_ALLOWED_EMAILS`, `STAFF_ALLOWED_USER_IDS`, `STAFF_ALLOWED_USERS`, and `STAFF_EMAIL_ALLOWLIST`; an empty allowlist denies staff access. The public donation submission route is mounted before the staff-only API gate.

## Meaning of `attend_entry_id`
The source code and project brief define it as the numeric ATTEND entry identifier linked to the donation in the companion workbook’s **“Linked ATTEND Entry ID”** field. It is separate from the internal UUID and the human-readable `item_id` (for example, a DS number); it is not a claim tracking number. The app’s development data assigned `12` to `ITM-003`, with new app entries starting at `13`. The queried production database does not yet have that field.
